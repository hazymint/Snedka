# Меню недели

Веб-приложение: рецепты, каталог продуктов по категориям, общий список покупок и семейные группы.

- **Сервер:** Node + Express + SQLite (better-sqlite3), регистрация (bcrypt), JWT.
- **Клиент:** React + Vite, Tailwind (CDN).
- **Семья:** при регистрации создаётся ваша группа; по коду приглашения в неё добавляются участники. Рецепты и список покупок — общие для всех членов семьи.
- **Тема:** светлая / тёмная / системная — переключатель в шапке (и на экране входа). Выбор сохраняется в `localStorage`; режим «системная» следует за настройкой ОS. Палитра задана CSS-переменными (`client/index.html`), классы используют семантические токены (`bg-paper`, `text-ink`, `bg-primary`, …).

## Запуск (локально)

Нужен Node.js 18+.

### 1. Сервер
```bash
cd server
npm install
cp .env.example .env        # задайте JWT_SECRET
npm run dev                 # http://localhost:3001
```
При первом запуске БД `menu.db` создаётся и наполняется базовым каталогом (77 продуктов, 103 рецепта).

### 2. Клиент
```bash
cd client
npm install
npm run dev                 # http://localhost:5173
```
Vite проксирует `/api` на сервер (порт 3001). Откройте http://localhost:5173 и зарегистрируйтесь.

## Прод-сборка клиента
```bash
cd client
npm run build               # dist/
```
Раздавайте `dist/` любым статическим сервером (nginx), а `/api` проксируйте на Node-процесс.
Tailwind подключён через CDN для простоты — для продакшена замените на сборку Tailwind/PostCSS.

## Структура
```
server/
  server.js        — Express, все эндпоинты
  db.js            — схема SQLite + сидирование
  seed-data.js     — базовый каталог и рецепты
client/
  src/
    App.jsx        — навигация, загрузка данных
    Auth.jsx       — вход / регистрация
    Recipes.jsx    — список и карточка рецепта
    RecipeForm.jsx — создание рецепта (каталог по категориям + поиск + новый продукт)
    Shopping.jsx   — общий список покупок
    Family.jsx     — семейная группа, инвайт-код, участники
    api.js, ui.js
```

## Заметки по безопасности
- Поменяйте `JWT_SECRET` на длинную случайную строку.
- За реверс-прокси добавьте HTTPS и rate-limit на `/api/auth/*`.

## PWA
Клиент устанавливается как приложение (манифест + service worker).
- Иконки и манифест лежат в `client/public/`.
- Service worker (`client/public/sw.js`) кэширует только статическую оболочку; `/api` и `/uploads` всегда идут по сети, чтобы данные не «застывали».
- SW регистрируется **только в прод-сборке** (`npm run build` → `npm run preview`), в dev он отключён, чтобы не мешать Vite.
- Для установки нужен HTTPS (или localhost).

## Картинки
- Обложка рецепта и фото к каждому шагу. Файлы грузятся на `POST /api/uploads` (multipart, поле `image`, опциональное поле `variant` = `cover`/`step`; до 12 МБ оригинала, только растровые изображения — SVG отклоняется).
- **Сжатие в два этапа.** В браузере картинка предварительно уменьшается через `<canvas>` (экономит мобильный трафик), затем на сервере `sharp` применяет EXIF-поворот, ресайз без апскейла (обложка ≤1280px, шаг ≤800px) и перекодирует в **WebP**. Рядом сохраняется миниатюра `…_thumb.webp` (≤400px) — её отдаёт сетка рецептов.
- Файлы хранятся в `server/uploads/`, раздаются по `/uploads/...`. Эндпоинт возвращает `{ url, thumb }`; в БД пишется только основной `url`, миниатюра выводится по соглашению об имени (`thumbUrl` в `client/src/ui.js`).
- **Сборка мусора.** При замене картинки или удалении рецепта неиспользуемые файлы (вместе с миниатюрами) удаляются с диска, если на них больше никто не ссылается.
- Изображения в списке грузятся лениво (`loading="lazy"`); в сетке сперва показывается миниатюра, при ошибке — полноразмерный файл, затем картинка скрывается.
- **Кадрирование обложки.** В форме обложку можно перетащить, выбрав видимую область; точка кадрирования хранится в `recipes.image_pos` (формат CSS `object-position`, валидируется на сервере) и применяется к миниатюре в сетке. На странице рецепта обложка показывается целиком (`object-contain`), поэтому кадрирование на неё не влияет.
- Шаги рецепта хранятся как `{ text, image }`. Базовые рецепты (текстовые шаги) подхватываются автоматически.
- Базовые рецепты идут с обложками-ссылками на файлы Wikimedia Commons (заданы в `server/seed-data.js` через `Special:FilePath`), отдельная загрузка не требуется. Если файл не найдётся, клиент скрывает картинку.
- В продакшене за nginx проксируйте `/uploads` на Node так же, как `/api`, или раздавайте каталог напрямую.

## Роли, видимость и реакции

**Видимость рецепта.** При создании выбирается «Только моя семья» (видят участники группы) или «Публичный» (видят все). В списке есть фильтр: Все / Мои семейные / Публичные.

**Лайки/дизлайки.** Любой авторизованный пользователь может поставить реакцию видимому рецепту. Счётчики хранятся в `recipe_reactions` (одна реакция на пользователя), повторное нажатие снимает её.

**Роли пользователей.**
- `user` — свои семейные рецепты (создание/редактирование/удаление), реакции.
- `moderator` — то же + редактирование/удаление **любых** рецептов, бан обычных пользователей.
- `admin` — всё + назначение ролей и бан кого угодно.

Первый зарегистрированный аккаунт автоматически становится **админом**. Управление — во вкладке «Админка».

**Бан по нику = бан по IP.** При бане пользователя все его известные IP (таблица `user_ips`, плюс последний) попадают в `banned_ips`. Любой запрос с этих адресов отклоняется (403). Разбан снимает и аккаунт, и связанные IP.

> Для корректного определения IP за реверс-прокси сервер использует `trust proxy`. Убедитесь, что nginx передаёт заголовок `X-Forwarded-For` (`proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;`). Бан по IP грубоват для общих/CGNAT-адресов — это ожидаемо.
